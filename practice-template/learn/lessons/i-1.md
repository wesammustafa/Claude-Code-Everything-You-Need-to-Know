## intro
- minutes: "about 20 minutes"
- why: "Make test-first load for feature requests, never for questions, and leave the commit to you."
- can: "turn a workflow you keep repeating into a project skill, choose which requests should load it, and review the change it produces."
- payoff: "turn a workflow you keep repeating into a project skill, choose which requests should load it, and review the change it produces."
- read: "[Extend Claude with skills](https://code.claude.com/docs/en/skills): every frontmatter field, arguments, supporting files and running a skill in a subagent."
- win-note: "From this level on, the lessons are written for macOS, Linux and WSL 2."
- need-repo: "One of your own repositories with a test command and no uncommitted changes"

## warm-up

### R1 | Warm-up | A long conversation, the same job
- tier: challenge
- skill: compact
- from: b-4
- where: claude
- beat: ask
- ask: After a long refactor, you'll keep working on the same link checker, and the context is nearly full. What do you do with the conversation?
- wrong: Clear it and start empty
- because: "The job is done and the next one is unrelated, so clear rather than compact."
- right: Compact it, keeping the decisions
- reveal: "The conversation you resumed holds the whole refactor, and you're staying on the link checker, so compact rather than clear:"

### R2 | Warm-up | Back to yesterday's work
- tier: challenge
- skill: resume
- from: b-4
- where: claude
- beat: ask
- ask: Yesterday you named the refactor conversation as you cleared it; this morning you fixed a typo in a new session. How do you get back to the refactor?
- right: Resume it by its name
- wrong: Continue the latest session here
- because: "`claude --continue` reopens the most recent session in this folder instead"
- reveal: "open the refactor conversation again by its name"

### R3 | Warm-up | A change went wrong
- tier: challenge
- skill: rewind
- from: b-4
- where: claude
- beat: ask
- ask: An experiment changed the wrong files, and you want Claude to remember why it failed. What should recovery keep?
- right: The conversation, with the code put back
- wrong: Both put back, the files and the conversation
- because: "Files and conversation back, to send a better prompt"
- reveal: "The files back, and Claude to remember what it tried"

### W4 | Worked example step 4 of 4 | Ask without naming it
- tier: guided
- skill: match-skill
- where: claude
- beat: predict
- ask: You ask a root-cause question and don't name the skill. What happens?
- option: Nothing: skills run only by name
- because: "Claude matches your request to the skill listing"
- right: five-whys loads from its description
- option: Claude reads skill bodies to pick one
- because: "not from the skill body"
- reveal: "Claude decides whether to load a skill from its description"
- beat: do
- skill: clear
- verify: self
- done-label: cleared
- run: "/clear"
- beat: do
- verify: self
- done-label: I saw it
- say: Then ask a question that matches the description without naming the skill.
- say: For example, in the practice copy:
- run: "Why does the test suite pass even though samples/guide.md has a broken link? I want the root cause, not a quick fix."
- note: "Look for a `Skill` tool call for `five-whys` before the investigation"
- hint: "If it does not appear, compare the request with the description, revise the request and try in a cleared conversation."
- why: "Each skill Claude can load on its own sits in the skill listing, which adds to your context on every turn."

### Y2 | Your turn step 2 of 5 | Choose the trigger
- tier: hinted
- skill: write-skill
- where: editor
- beat: do
- verify: no-match .claude/skills/tdd/SKILL.md \bTODO\b fresh
- goal: "In your editor, finish it:"
- do: "replace `TODO` in the description with what the skill does followed by "Use when" and the feature requests it fits;"
- do: "write the Green and Refactor steps, keeping the Red step's style;"
- hint: "Decide which requests should load this skill before you edit it."
- hint: "Write the description for requested feature work; keep explanation-only questions outside its stated scope."
- beat: ask
- ask: A teammate's release skill tags a version and pushes it. Should Claude load it on its own?
- right: No: only when someone runs it by name
- wrong: Yes: its description keeps it on topic
- because: "Use it for a workflow with side effects or whose timing you must control, such as a commit or a deploy"
- reveal: "`disable-model-invocation: true` makes invocation manual and keeps the description out."
- beat: do
- verify: no-match .claude/skills/tdd/SKILL.md ^disable-model-invocation: true fresh
- say: Then make the last edit to the skill.
- do: "delete the `disable-model-invocation: true` line so this skill can load automatically as well as run by name."
- hint: "`disable-model-invocation: true` makes invocation manual and keeps the description out."
