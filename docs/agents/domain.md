# Domain docs

Use a single-context layout: `GLOSSARY.md` at the repo root and `docs/adr/` for architectural decisions.

## Before exploring

- Read the root `GLOSSARY.md` if present.
- Read relevant ADRs under `docs/adr/` if present.
- Follow the relevant `.scratch/` feature README's links to existing context and decision records.

If the glossary or ADR directory is absent, proceed silently. Create domain docs through domain modeling when terms or decisions are resolved.

## Vocabulary and decisions

Use the glossary's terms in tickets, proposals and implementation work. Surface meaningful vocabulary gaps when they arise.

Flag any conflict with an existing ADR explicitly before proposing to change the decision.
